# How it works

## Layout

| Path | What |
|---|---|
| `js/games.js` | The games in the hall, in the order their cabinets stand, each with its demo and the high-score tables (one per level) the demo shows. To change the order, move a line and run `./dev order` (`scripts/order-hall.mjs`), which puts the cabinets in `index.html` in the same order; the hall stays plain HTML, so nothing moves after the first paint. `tests/site.test.js` fails while the two differ. |
| `index.html`, `js/hall.js` | The hall: one arcade cabinet per game (below). A ready game plays itself on its screen; the rest say "Coming soon". A demo's code is fetched only when its cabinet comes within 200 px of the screen, so the hall's first load stays small however many games there are. Without JavaScript the cabinets are plain links. |
| `games/<game>/` | One folder per game: `index.html` (its page), `main.js` (the page's code), `rules.js` (the rules, no DOM, tested), `demo.js` (attract mode for the hall). |
| `scripts/templates/game/` | The starter game `./dev new-game` writes (`scripts/new-game.mjs`; see [adding-a-game.md](adding-a-game.md)). Its `index.html` is also the game page the others share their HTML with: the head's first lines (charset to build stamp), the bar's Arcade link and buttons, and the initials dialog. Change them there and run `./dev sync` (`scripts/sync-pages.mjs`), which copies them into every page (the head into the hall too) and writes each page's `modulepreload` list from the imports of its script. The pages stay plain HTML. The title, help, hall-of-fame caption and the game itself stay in each page. `tests/sync.test.js` fails while a page differs from what `./dev sync` writes. |
| `js/` | Shared by the hall and every game (below). |
| `styles.css` | The one stylesheet. Colour tokens `--neon-*` are read by canvas code too. |
| `_headers` | Security headers for Cloudflare Pages (strict CSP). |
| `tests/`, `scripts/`, `dev` | Unit tests and scans (`./dev test`), the browser layout check (`./dev layout`), the local helper. |

## Shared modules (`js/`)

| Module | Job |
|---|---|
| `loop.js` | `requestAnimationFrame` loop with a fixed timestep; stops in hidden tabs. |
| `attract.js` | Runs a game's demo on a cabinet canvas: sharp at any pixel ratio, paused off screen, one still frame with reduced motion, redrawn only when the demo says something changed. |
| `canvas.js` | `sharpCanvas`: a canvas drawn sharp at the screen's pixel ratio, at most 2x (more costs time on a phone and shows nothing), resized only when its size or the ratio changed. `stillFrames`: with reduced motion, a game that moves on its own draws a frame only when what is visible changed. |
| `logo.js` | The Notchup logo in parts (gear, compass, arrow), with the same shapes as `assets/mark.svg` (`tests/logo.test.js`), as inline SVG or on canvas. In the hall the logo is the plain mark, a link to notchup.fi (the demo screen also draws it); on a win the gear turns four teeth and the arrow rises. In a game's console, `consoleLogo` draws it and notches it up, sparks it or resets it. |
| `sound.js` | Sound effects made with the Web Audio API, no files. The audio context starts on the first sound, which always follows a tap. A won game plays `fanfare`: the win tune with the gear notching up four times under it. |
| `screens.js` | The screens a demo ends with: the logo notching up under a line of text, then this browser's top 5 for each level that has a score (4 s a page, the level named in magenta; "no scores yet" when none has). `createTail` runs that for every demo. |
| `city.js` | The night city of notchup.fi: a row of buildings with a few lit windows, seeded (Lob's street, Notch Up's skyline). |
| `sparks.js` | A calm burst of sparks in the neon colours that drifts out and fades, no flash (Patch Night's right zap, Notch Up's cheers). |
| `shuffle.js` | `shuffled`: a deck in random order from a seeded `rand` (Pair Up's cards, Night Deal's 52); apart from `random.js` because the hall's demos load that and have little room to spare. |
| `random.js` | A seedable random number generator, so rules and demos can replay in tests, and `pickLine`, which picks a cheer's line with it, never the one before. |
| `cells.js` | `fitCell` sizes a board of square cells to its frame (and marks the frame `scrolls`), `cellName` is "Row 2, column 3"; Fuse Box and Bent Beam. Pair Up still sizes its own deck (it has a gap between cards). |
| `challenge.js`, `challenge-ui.js` | A challenge: one score packed into 13 base32 characters in a link's `#c=` part (board, score, initials, day, checksum: 65 bits). It is an encoding, not encryption: anyone can read or forge a code, and the checksum only catches typos. `challenge.js` packs and reads it (a code is ignored when the checksum, board, initials or date is bad or the score is below 1; there is no upper limit per board, which is why challengers are labelled not verified); `challenge-ui.js`, loaded only when needed, shares a link and shows the card that greets a visitor. A link opened from outside the arcade (a chat app) has nothing behind it, so the card also puts the hall behind the game in the history (`hallBehind`): the page's entry takes the hall's address with the game's name (`/#lob`, as the hall writes it) and the game is pushed on top, and when Back lands on that entry a reload loads the hall for real, on that game's cabinet so the zoom back and the centring work, replacing the entry so Back from the hall leaves cleanly. While the hall loads (a chat app's own browser has never seen it, so it can take seconds) a small "Back to the arcade…" card shows, so the game does not look stuck. A visitor who came from the arcade is left alone. Opening a link saves nothing; the card's Save challenger adds it to the Friends table (`memory.js`, rules in `scores.js`: best 5 per board, 50 in all, dropped 4 weeks after saving). The board list's order is part of every link, so it only grows at the end. |
| `scores.js` | High score rules, the same for every game: top 5 per board, ordered by time (`low`) or points (`high`), initials of three characters, letters (A–Z and Å Ä Ö) or dots, at least one a letter (`PEK`, `P.K`). An entry may carry up to three numbers only its game counts (`extra`). Dates read "21Nov26", short enough for a phone. `weekOf` names the week a moment falls in by its Monday in Helsinki (`2026-11-23`), so a week runs Monday 00:00 to Sunday 23:59 Helsinki time for everyone, summer time included. Pure. |
| `fame.js` | The hall of fame table, laid out the same in every game: place, initials, the score, the game's own columns, the date. A game names its score column and adds columns for what it alone counts: Lob the rivals beaten, Patch Night the share right first time and the average answer time, Notch Up the most perfect drops in a row. Fuse Box needs only its time. Entries saved before a column existed show a dash. The table always has five rows, unplayed places as `---`, and the small print under it keeps the room of its longer line, so the dialog is the same size on every table. The columns are fixed too (a narrow place column, the rest equal), and the Friends table has the game's own columns as well (a dash where a friend has none), so switching tabs never moves a column. Below 400 px wide the date column is hidden: with a long score or Patch Night's two extra columns it would wrap a row or push the table wider than the dialog. `createFame` is a game's whole hall of fame: three buttons above the table, All time, This week and Friends, switch between the tables of the current level (the week's says it starts over on Monday; Friends holds challengers saved from links, with Compare, Delete and Clear under it, shown only while there are friends saved, so the dialog is the same size in the other two tables and fits a phone without scrolling; with friends saved, the Friends table is one button row taller). It also adds the Challenge a friend and Show QR buttons, a folded "How does sharing work?" note under the table, loaded the first time the dialog opens (what a link is, that nothing is sent to a server, that scores are not verified), and greets a link (`challenge-ui.js`); the game's id comes from its board name and its name from the page's heading. When a run ends, `offer` asks for initials if the score makes the top 5 of either table (the dialog says "New weekly high score" when only this week's), saves it with the game's own numbers and opens the table with the new row marked (on All time when it made that), so every game ends a run the same way. |
| `record.js`, `record.css` | The big cheer for a new record: when a run ends with a score that tops the best all-time score saved before it (a first score is not a record, and a weekly-only best does not count), a centred "New record!" banner with the score fades in for 3.5 s, with a small pop under `prefers-reduced-motion: no-preference`. It never takes focus or a tap, does not flash and is read out politely. Loaded by `fame.js` (`offer`) only when a run makes the top 5, with its own stylesheet, so no page pays for it up front (Night Deal's first load is within a few bytes of its budget). |
| `rivals.js` | The cheer for passing a friend. A game calls `fame.startRun()` when a run begins and `fame.passing(score)` whenever its score changes (the timed games call `fame.passing(ms, true)` once, at the win: a time passes a friend only when the run is done). `fame.js` loads `rivals.js` only when a friend is saved for the level, so a page without friends pays nothing. A friend is passed when the score is strictly better, and is named once per run; friends passed together share one line. The line is one `role="status"` element at the top edge, `pointer-events: none`, shown for under 3 s with an opacity fade (none with reduced motion), plain text only. The wording, colour (gold, cyan, magenta) and side change each time. |
| `qr.js` | A QR code encoder of our own (byte mode, error correction M, versions 1 to 6: up to 106 bytes, enough for a challenge link). `challenge-ui.js` imports it only when Show QR is tapped and draws it as an SVG, dark on white. `tests/qr.test.js` pins the modules of codes made by an independent encoder, every mask. |
| `memory.js` | The only code that uses `localStorage`: one key, `arcade:v1`, holding the sound setting, the last initials, the tables (all time, and this week's, dropped once a new week starts), the Friends table (challengers saved from links), and a short list per level of the times-table facts missed (Patch Night, at most 20, as keys like `7x8`). Nothing leaves the browser. Works without storage. |
| `initials.js` | The "New high score" dialog (native `<dialog>`), the same markup on every game page (`tests/site.test.js`): the place, the score in the game's own words ("34 floors", "42.3 s"), and the field. It is modal (a tap outside does nothing), focus starts on its heading so a phone's keyboard opens only when the field is tapped (with a mouse the field is ready to type into), the field holds the initials typed last in any game, Enter in the field saves, and typing keeps only what can become valid initials. |
| `grace.js` | A short grace period (0.8 s) for controls that appear the moment a run ends: dimmed, and taps, keys and Escape do nothing until it is over (an initials dialog closed by Escape then opens again). A held button gets the focus when the hold ends, or when a dialog open by then closes. Notch Up and Patch Night, played by fast tapping, use it on the initials dialog's buttons and on their cards' button (Patch Night's break card too); Fuse Box and Lob do not need it. |
| `settings.js` | What every page has around its game: the sound switch (an icon button), the version, and a game's Arcade link. When the hall is the page before, that link goes back in history, the same as the back button; reached any other way, it opens the hall at its top. |
| `dialogs.js` | The help and hall of fame buttons in a game's bar (`wireDialogs`), and the question before leaving a run in progress (`confirmLeave`; Fuse Box uses it for New panel and level changes). A game that moves on its own (Notch Up, Patch Night) waits while any dialog is open and ignores input under one (`dialogOpen`); Pair Up deals its next round only once every dialog is closed (`whenDialogsClosed`). |
| `levels.js` | A game's levels: the radios above the board, and the level in the link (`?level=hard`; the first level keeps the link clean). The names come from the game's `LEVELS`, and `tests/screens.test.js` checks the hall's score pages list the same ones. A game that would lose a run in progress passes `allow` to `pickLevel`; when it answers no, the radios and the link stay on the level they were. |
| `grid.js` | A board of buttons in rows (Fuse Box's panel, Pair Up's deck): one tab stop that follows the focus, and the arrow keys, Home and End to move around it. |

## Cabinets and the zoom into a game

- A ready cabinet's screen always carries a solid dark plate, "CLICK TO PLAY" ("TAP TO PLAY" on a touch screen), in 16 px text with a 2 px border in the cabinet's colour (`--plate`, gold unless the cabinet sets its own), like a sticker on the glass, so it reads the same over any demo. It swells 6 % and back over 2.4 s (transform only, never flashing; still with reduced motion). It is CSS (`.screen::before`) and not part of the demo's cycle, so it is seen whatever the demo is showing. A tapped cabinet that is slow to open (300 ms) dims its screen and shows the logo notching round (`.opening`, set by `js/hall.js`, cleared when the page is shown again), so a slow connection does not look like a freeze.
- Each cabinet is an arcade machine drawn in CSS only, no images: a lit marquee with the name, the screen in its bezel with a still glass sheen, a control panel that sticks out past the sides (a stick and three buttons, decoration hidden from screen readers), and the base with the pitch (wide screens only) and a lit Play plate. A game still coming has its marquee unlit, its screen off with a faint Notchup mark, and "Coming soon" on its base. Nothing on a cabinet moves on its own; only the demo on a ready screen does.
- The cabinets sit in a grid that is two wide from 768 px and four wide from 1120 px; a last cabinet that would stand alone in its row (or the last two or three) is centred.
- Opening a game puts its name in the hall's address (`#notch-up`), so coming back with the back button, or with a game's Arcade link (which then goes back in history too, `js/settings.js`), centres the cabinet just played rather than the one the browser happened to remember (`js/hall.js`), and the screen shrinks back into it. The name is not an element id on purpose: the browser would then jump the cabinet to the top of the screen itself, after the centring. Phones: each ready game is one big cabinet, one under another; games still coming share a row below them. From 768 px: two cabinets side by side, and from 1120 px all four in a row.
- Opening a game, the cabinet's screen grows into the game's play area (`.game-main`) in 0.3 s, and going back it shrinks into the screen again. This is a cross-document view transition, pure CSS: `@view-transition` opts both pages in, the screen and the play area share a `view-transition-name` (one per game, since a name may be used once per page), and the growing box is a solid lit screen so the pages never show through each other. The demo's picture fades out in 0.12 s, before it is stretched much. The game's own page is photographed at its first frame, so each game page's script is `blocking="render"` (the page waits for `main.js` to build the board) and a game that sizes its board from its frame calls its `fit()` once at start instead of waiting for the first resize callback; otherwise the zoom ends on an empty or small board that then jumps to full size (`tests/site.test.js`). Browsers without `blocking` just show the board a moment later.
- Browsers without cross-document view transitions get a normal page load. Under `prefers-reduced-motion: reduce` the `@view-transition` rule is off, so every visitor who asked for less motion gets a normal page load too. `tests/site.test.js` checks both the names and this.

## Fuse Box

- A panel is a grid of fuses; some are blown. Testing a good fuse lights it and shows how many of its eight neighbours are blown; a fuse with none lights its neighbours too. Testing a blown fuse sparks and the game is over. Test every good fuse to fix the panel.
- The first test is always safe, and so are its neighbours: the blown fuses are placed after it.
- Tag a suspected blown fuse: the Test / Tag switch under the panel (in Tag, the panel's frame turns gold and every tap tags), a long press (with a short buzz where the phone can), a right click, or the T or F key. Testing a lit number again when all its blown neighbours are tagged tests the rest around it, also in Tag mode.
- Levels: Easy 8×8 with 10 blown, Medium 13×9 with 22, Hard 18×10 with 40. On a portrait screen the panel turns (9×13, 10×18) so cells stay big; the fuse count is the same, so times compare. When the cells of that shape would be under 24 px (a short phone, Hard), `fitted()` takes another shape with the same number of fuses and the biggest cells, for instance 12×15 instead of 10×18, so the panel fits without scrolling (never a strip: at most twice as long as wide; the same hall of fame table holds either shape); only a screen as small as 320×568 still scrolls it inside its frame, and there a drag on the panel scrolls that frame (the `scrolls` class) and nothing else. The level is in the link (`?level=hard`).
- Shared bar and landscape: on phones (under 480 px) the back link is just the arrow, and the title shrinks (never under 16 px) and ends in an ellipsis rather than run under it. A touch screen held sideways and under 480 px tall is too short for any board, so a plate (`body.game::before`, in `styles.css`) covers the game with "Turn your phone upright" until it is turned back; tablets and laptops are left alone.
- The page fits the screen with no scrolling: a bar (back, title, help, hall of fame, sound), the levels, the counters with the logo, the panel, one status line and the two buttons. The panel takes the room that is left and `main.js` sizes the cells to the biggest that fits, 24 to 52 px; below 24 px the panel scrolls inside its frame. Help and the hall of fame open in dialogs. While a run is on (after the first test), New panel and a new level first ask "Leave this panel?" in a small dialog whose main button is Keep playing; Escape keeps the run too. The clock keeps running behind it. A panel not yet started, won or lost starts over at once. The panel is a grid of real buttons with one tab stop: arrow keys move, Enter tests, and each button says its row, column and state to a screen reader.
- On a win the logo's gear turns four teeth and its arrow rises. A time that makes the top 5 of its level asks for initials, then shows the hall of fame.
- Attract mode (`demo.js`) plays Easy by the same rules, calmly: about one move a second, the cursor stepping to a fuse near the last one, no glow or flashing. Then the logo notches up and this browser's top 5 shows, for every level with a score.

## Lob

- Two rooftops face each other across a street at night. You throw glowing bulbs at the rival's billboard on the right; the rival throws at yours, which shows the Notchup mark. The target is always the billboard, never the player: the sign being aimed at wears gold corner brackets, and the prompts and help say so. A billboard that has taken three hits goes dark, and its owner loses. Rooftops do not break.
- A throw has an angle (5° to 85°, up from flat, toward the other roof) and a power (10 to 100). `rules.js` holds the whole simulation, with no DOM: fixed 1/120 s steps, gravity, and a sideways push from the wind. A bulb that meets the other billboard hits; one that meets a roof, your own sign, the street or the edge misses. The first wind of a match and a new wind after every throw are whole numbers from −9 to 9 (the rival sets the limit), shown by the number beside the readout and by the smoke of the chimney in the middle of the street, which leans with it.
- The chimney: a tall, slim chimney stands in the middle of the street, between the two roofs, so a flat throw at full power hits it (`fly` reports `where: 'chimney'`, a miss told as "hit the chimney") and the bulb has to be lobbed over it. Its top is `stack` above the higher roof: 18 for the first rival, 1.5 more for each next one, up to 26 (two players on one device, which have no rivals, get the same growing chimney from match to match; `FIRST_STACK` and `rivalFor(level).stack`; 1.5 times as much on an upright screen, as the roofs are). Tests keep three promises on every street, side and rival: no throw up to 25° at full power hits the billboard, a flat one hits the chimney, and a lob always exists (`solvePower` ignores the chimney, so it measures the throw, not the street). The cached street picture includes the chimney, so its key has the chimney's height.
- Aiming: drag back from your roof and let go (touch and mouse; a drag under 14 px is a tap and does nothing), or − and + for each value and Throw, or the arrow keys (up and down for the angle, left and right for the power) and Space. A short dotted guide shows only the start of the arc. The last throw stays on screen as a faint dotted trail, the one before it fainter.
- Solo is the main mode and opens straight into a match against the computer. It is a run: rival after rival, each aiming a little better (`skill` 0.3 up to 0.9) with a little more wind (up to 9). The run ends on your first loss. A won match is worth 100 points and 10 more for every throw under ten. A run with points that makes the top 5 asks for initials (board `lob:solo`, points, higher wins, kept in this browser only). Two players on one device is a small switch under the street; it has no scores.
- The computer aims like a person (`aimComputer`): a rough first guess that reads only part of the wind, then after each throw it scales its power by how far it carried and adds what it thinks the change in wind is worth, so it overcorrects when the wind changes a lot. If a bulb hit the chimney it also raises its angle, 2° at a time, until the throw it has worked out would clear it. Its hand wobbles less as `skill` rises.
- Each rival has its own sign and its own stretch of street (`STREETS`: roof heights and the skyline) and its own chimney height. On an upright screen the rooftops are closer and taller, so the tall screen is used for higher arcs; the shape is chosen when a match starts.
- The picture (`scene.js`) is the same city as notchup.fi in the arcade's colours: navy night, stars, two skylines with lit windows, billboards on steel frames. It is drawn on one canvas; the street is cached and copied. The camera is still, nothing shakes or flashes, the chimney's smoke drifts slowly (redrawn about 15 times a second, not at all in a hidden tab or with reduced motion), a hit is a soft ring and the rival's letters go dark. With `prefers-reduced-motion` a throw is shown at once instead of flying.
- The street keeps its size all game: the status line is always two lines high (messages stay short enough), so a longer message never takes room from the picture and rescales it.
- Win a match and the logo's gear turns four teeth and its arrow rises, as in Fuse Box.
- Attract mode (`demo.js`) has two computer players trade throws by the real rules at a calm pace, then the logo notches up and this browser's top 5 shows.
## Patch Night

- A times-table bug zapper. Night in a dark server room drawn as a circuit board; the Notchup logo sits in the middle and its arrow turns to aim. Each wave asks one question, shown above the board (a live region for screen readers), and a bug crawls in slowly along every lane, each carrying a number; exactly one is right. The page has a bar, the levels, the score, the three lights and the streak, the question, the board and one status line, and fits the screen with no scrolling. Help and the hall of fame open in dialogs, and the game waits while one is open.
- Zap the right bug: a short gold line fades, a ring of gold, cyan and magenta sparks drifts out of the bug and fades in 0.8 s (slowing down, no flash; not drawn with reduced motion), the bug curls up and fades, the gear's wave is over and the next one starts after a short pause. Zap a wrong one: that bug is pushed back a little, the other bugs creep a little closer, the wave's worth drops (by 25 for the first wrong zap of a wave, 50 for the second, 75 for the third), the others creep closer by more each time, the streak ends, a low buzz. A third wrong zap in one wave is guessing, not slipping: it puts out a light, so trying every lane never pays; one or two slips cost no light. The right bug reaching the logo puts out one of three lights; wrong bugs that reach it just fade. Three lights out ends the run. Speed starts slow and rises a little with each right answer up to a cap, and drops a little after a missed wave.
- Levels, in the link (`?level=medium`): Simple (tables 1 to 5 and 10, four lanes, wrong answers far from the right one), Medium (tables 1 to 10, eight lanes, close wrong answers: the neighbours in the same tables, e.g. for 7 × 8: 48, 54, 63, 49), Hard (up to 12 × 12, eight lanes, close wrong answers, and sometimes a missing factor, `7 × ? = 56`, where the bugs carry factors). The lane count belongs to the level, not the device, so scores compare. No answer appears twice in a wave.
- Learning: a fact that was missed (a wrong zap, or the right bug getting through) comes back two to four questions later, and again five to eight questions after a right answer, until it has been answered right twice (7 × 8 and 8 × 7 are the same fact). Game over lists the facts missed in the run ("Practise these"). This browser remembers up to 20 missed facts per level (`memory.js`, `patch-night:<level>`); a new run asks the first few early, and a fact answered right once is forgotten again. Nothing is sent anywhere.
- Breaks: after every 10 answers (a wave that ends zapped or arrived) the game pauses on a card over the board: a short cheer (one of a few lines for how many were right first time, picked at random and never the same line twice in a row; on every 50th answer a special "fifty" cheer instead), "N of 10 right first time", the average time of those answers, and up to two hardest facts (misses first, then the slowest right ones). Continue starts the next wave and a new set is counted; it works after a short grace period (`js/grace.js`), so a tap meant for a bug cannot skip the break. Losing the last light on the tenth answer ends the run instead. Nothing is stored or sent beyond the missed-facts memory above; the card is static, with no motion.
- Controls: tap or click a bug or anywhere in its lane (the nearest lane to the tap, by angle) fires at once. On a keyboard you aim, then fire: the arrow keys turn the turret (one arrow is a straight lane, two held together are the corner between them; on four lanes the last arrow wins), Q E Z C and the number pad (8 9 6 3 2 1 4 7) aim too, and Space or Enter fires at the lane it is set on. The aimed lane's trace turns gold and the logo's arrow points along it. The lanes are also a ring of real buttons over the canvas, labelled like "Up: 42", each at least 44 px, which keeps screen reader play whole (activating one fires at that lane).
- Score: a right zap is worth what the wave is worth when it lands, times the streak multiplier (×2 at 3 in a row, ×3 at 6, ×4 at 10). The worth starts at 200 and counts down to 100 as the right bug crawls to the logo, and the wrong zaps in the wave take 25, then 50, then 75 off it (`worth()` in `rules.js`). The page shows it, with the multiplier, in the board's top right corner, so a quick answer is plainly worth more. Top 5 per level (board `patch-night:<level>`, points, higher wins).
- Calm: bugs crawl, nothing shakes or flashes. With `prefers-reduced-motion` bugs step forward in ten still steps instead of gliding, the zap is a still line that disappears, and a frame is drawn only when something changed.
- `rules.js` holds everything with no DOM (waves, wrong-answer choice, the review queue, scoring), seeded and tested; `scene.js` draws the board for both the page and the demo; `demo.js` has the logo zap the right bug about every 1.5 s on Simple for a few waves, then shows this browser's top 5.

## Notch Up

- A tower stacker. Build the Notchup tower floor by floor over the night city. A new floor slides back and forth above the top of the tower; drop it, and whatever hangs over the edge of the floor below is cut off and fades where it was (it does not fall), so the next floor is that much narrower. A floor that misses the tower completely ends the run.
- A drop within 4 units of the floor below (the world is 200 units across, a floor starts 90 wide) is perfect: it snaps on exactly, keeps its width and leaves a gold seam that fades. From the third perfect in a row, every perfect wins 8 units of width back, up to the starting width. The sliding floor never goes past the edge of the picture (`swingOf`); it starts from the side opposite the one before and gets a little faster with every floor, up to a cap.
- Score: floors built. Top 5 (board `notch-up:tower`, higher wins). The console shows the floors, the logo and this browser's best.
- Every tenth floor has a magenta neon band and the logo in the console notches up (gear four teeth, arrow rises). Cheers, as on notchup.fi but calm: at 10, 50 and 100 floors and every hundredth after, and on the first floor past this browser's best when that best is 10 or more (the record wins over a round number on the same floor). A cheer shows the count ("10 FLOORS"), a big praise word and a dry building-site line under it, both picked at random from lists in `rules.js` that grow with the milestone and never repeat the line before; the words swell in and fade over 2.6 s while a few bursts of sparks drift out in the sky (3 for 10 floors, 5 for 50, 8 for 100 or a record). A milestone also helps: the crane builds that floor wider (20 units at 10 floors, 40 at 50, back to the full width at 100 and after), and the floors after it start from that width; a gold seam marks it. The status line says all this for screen readers. No BAM, flash or shake: a drop is a timing call, so nothing covers the tower.
- Controls: tap or click anywhere on the tower, or press Space or Enter (they drop the moment the key goes down). One real button, "Drop the floor", lies over the whole picture for the keyboard and screen readers. A phone would flash that whole button on every tap, so its tap highlight is off; instead the frame lights up softly (a ring inside the border fades in and out in 0.45 s, gold for a perfect drop, `opacity` only) and the dark windows of the floor just built glow and fade back in 0.5 s. Neither runs under reduced motion.
- The picture (`scene.js`) is one canvas: sky and stars and the distant city (`js/city.js`) are drawn once off screen and copied; the city sinks slower than the tower as the camera rises, so the tower climbs out of it. Only the floors in view are drawn, and a window is lit or not by its floor and column, so a tall tower costs no more than a short one. The Notchup logo hangs over the lobby. The camera eases up so the sliding floor stays at about 60 % of the height.
- Reduced motion: the camera jumps instead of easing, the sliding floor moves in steps of 3 units and is judged where it is drawn (`moverX`), the words show without swelling, there are no sparks, and a frame is drawn only when something changed.
- Attract mode (`demo.js`) starts with four floors up and drops about once a second, most drops perfect and the rest a little off, past the tenth floor's cheer; then the logo notches up, this browser's top 5 shows, and it starts over.

## Pair Up

- A memory game. A deck of face-down cards, two of each face. Turn two cards: a pair stays up, a wrong pair stays showing for 0.9 s and turns back down, and costs a chance. The level gives the chances (Easy 4, Medium 5, Hard 6, shown as lamps) and every pair found lights one back, never above the level's number. A cleared deck lights lamps back on top of its last pair's (Easy 1, Medium 1, Hard 2, never above the level's number), so a run that was down to its last lamp gets a margin for the next round. Finding every pair clears the round: a cheer card shows for 2.6 s (or until a tap on Next round), then a fresh deck of the same size is dealt (after the cheer, or when help or the hall of fame is closed if one is open; the status line says the next round is coming, and 2.6 s is a few seconds of reading for a short line) and the run goes on with the same score and chances, so a run lasts until all the lamps are out. Rounds are not capped. Turning any card while a wrong pair is showing turns that pair back down at once (so one of the two can be turned again straight away).
- Faces: letters (picked from 17 that are hard to mix up) and small pictures drawn from the other games: the Notchup logo, Lob's bulb, Fuse Box's fuse, a floor of Notch Up's tower, and four bugs (a beetle drawn to match Patch Night's, a ladybird, a spider, a butterfly; `faces.js`, one canvas drawing shared by the page and the hall's demo). Each face has a colour (letters share four), so a pair looks alike; each bug has its own colour (beetle green, ladybird magenta, spider cyan, butterfly gold) and its own outline (plain back and six legs, spots, eight legs, wings).
- Levels, in the link (`?level=hard`): Easy (6 pairs, 3 sprites of which 1 is a bug, and 3 letters), Medium (8 pairs, 4 sprites with 2 bugs, and 4 letters), Hard (10 pairs, 5 sprites with 3 bugs, and 5 letters): more bugs in the deck make it harder. The deck is tall (3×4, 4×4, 4×5) on a portrait screen and wide (4×3, 4×4, 5×4) on a landscape one, chosen when the game starts, but the number of pairs belongs to the level, so scores compare.
- Score: 100 for a pair, 50 more for every pair found right after another (a wrong pair ends the streak), and for every round cleared up to 450 for the chances left when its last pair was found (all of them is 450, fewer win their share, so the levels with more chances do not pay more). A new round starts its streak over. Top 5 per level (board `pair-up:<level>`, points, higher wins), with the pairs found in the whole run as the game's own column.
- The end of a round: every face lights gold, then a card shows the logo notching up (gear four teeth, arrow rises), a cheer and the score. The end of the run: the faces still down show for 1.6 s, then a card says how many rounds and pairs it took, and a score in the top 5 asks for initials. The cheer is a praise word and a dry line, picked at random from `rules.js` for the run (no wrong pair at all: Flawless; one or two: Sharp; more: Phew) and never the same line twice in a row. No flash, no shake. The deck ignores taps by then, the cheer or the end comes 0.7 s or more after the last tap, and the initials dialog holds its buttons for the usual 0.8 s grace.
- Controls: tap or click a card. The cards are real buttons, "Card 3, face down" or "Card 3: letter K", with one tab stop and the arrow keys moving around the deck; Enter and Space turn a card. The status line (a live region) says what was turned and how many chances are left. Cards are at least 44 px; a card flips in 0.25 s with a CSS rotation (none with reduced motion, where it just changes). Nothing else moves.
- `rules.js` holds everything with no DOM (the seeded deal, turning, score, cheers), tested; `faces.js` draws a face and a back; `demo.js` plays an easy deck by the real rules, one wrong pair first and then every pair, then the logo notches up and this browser's top 5 shows.

## Night Deal

- A calm card game: the seven-column patience. Build the four stacks (one per suit, spades, clubs, hearts, diamonds) from ace to king. Seven columns hold cards face down under a face-up run; a card goes on one of the other colour and a rank higher, a run moves together, and only a king goes in an empty column. Draw pile and discard pile as usual, turning the discard pile back over when the draw pile is empty. Two levels, in the link (`?level=draw-3`): Draw 1 and Draw 3 (cards turned over at a time).
- Every deal can be won. `scripts/night-deal-solver.mjs` is a depth-first search that wins a deal or gives up after 100 000 positions, and `scripts/night-deal-deals.mjs` runs it over the seeds 0 to 2047 with draw 3 (which also wins them with draw 1) and writes the proven ones as a 256-byte bitmap in `games/night-deal/deals.js` (about 70% of deals; a deal the search cannot settle is left out). The page picks one of those seeds, so no solver ships and a deal costs nothing to make. "Winnable" means a win exists, not that it is easy to see. To change the list, run the script (about twenty minutes) and commit `deals.js`.
- Tap a card and it goes where it fits: a single card to its stack if it fits, else to the column that hides the fewest face-down cards (the leftmost of equals). A tap in a column moves that card with the ones on top of it. A tap on the draw pile deals. Or drag a card or run (6 px before a press becomes a drag; a drop lands on the pile it overlaps most that takes it; otherwise the cards slide back). Undo is unlimited and takes back one move; it counts as a move and does not turn the clock back.
- Time: counted from the first move, paused while a dialog is open or the tab is hidden (`clock.js`), stopped when the win is certain (every card face up, nothing left to draw: then a Finish button plays the rest onto the stacks, 0.14 s apart) and never drawn; the console shows the moves, which change only when you act. Score: the time of the win in ms (`night-deal:draw-1`, `night-deal:draw-3`; lower wins; at most 4.6 hours, what a challenge link can pack), with the moves as the game's own column.
- No moves left: after the table has been still for 0.4 s, `isStuck` looks through every position the draw pile and shifting cards lead to (up to 3000) for a card that can reach a stack, leave the discard pile, or be turned over by moving a whole run. If there is none, the status line says "No moves left. Undo, or deal again." and Deal again turns primary. It never blocks play.
- The table is one canvas, drawn by `scene.js` from the geometry in `layout.js` (pure, tested: card size from the width and the height, fan of each column, what is under a point, where a dropped run lands). Suits are drawn as shapes: spades and clubs cyan, hearts and diamonds magenta. Cards are at least 30 px wide (40 on a 320 px phone) with 16 px letters; face-down cards fan 4 to 6 px, face-up ones by at least a letter's height. The cards that moved slide for 0.13 s (none with reduced motion).
- Controls: over the canvas are 14 real buttons in two rows of seven (draw pile, discard pile, undo, four stacks, seven columns) with one tab stop and the arrow keys moving around (`gridKeys`); Enter does what a tap does, `[` and `]` choose how many cards of a column, `M` picks cards up and Enter on a place puts them down (the places that take them are outlined; Escape puts them back), `U` undoes. Labels say what is on each pile; the status line says each move.
- `rules.js` has the rules with no DOM (state, moves, `bestMove`, `isStuck`, `canFinish`), tested; `demo.js` replays a recorded winning game of draw 1 (103 moves, checked by a test) on the cabinet, then the logo notches up and this browser's top times show.

## Bent Beam

- A mirror puzzle. A lamp housing on the left edge fires a beam to the right across a square board. Walls stop it, mirrors bend it ("/" and "\"), and a lamp lights where the beam passes through it (the beam goes on). Tap a gold mirror to turn it the other way; white mirrors with rivets are bolted down. Red crosses are short circuits: the board is fixed only when every lamp is lit and the beam crosses none of them (a cross the beam crosses fills in red and the status line says so). The status line says how many lamps are still dark.
- Levels, in the link (`?level=hard`): Easy (5×5, 7 mirrors, 2 walls, 2 lamps, 2 shorts), Medium (6×6, 11 mirrors of which 2 bolted, 3 walls, 3 lamps, 3 shorts), Hard (7×7, 15 mirrors of which 3 bolted, 5 walls, 4 lamps, 5 shorts). The board is square at every size.
- A board is made backwards so it always has an answer: walls and mirrors go down at random, the beam is traced, the lamps go on empty cells it crosses after its first bend, the short circuits on empty cells beside its path that it does not cross (and the answer's beam must hit at least 4, 6 or 7 mirrors), the bolted mirrors are picked from the ones it hits, and then the turnable mirrors are turned until no way of winning (any answer, not only the one it was made from) is within 2, 3 or 3 turns (so it takes at least 3, 4 and 4), so no board is won by a tap or two, and the board's `par` (its fewest winning turns, found by trying every way of turning 0, 1, 2... mirrors, about 2 ms) is kept; the rare seed with no such board gets one turn less. A beam can never loop: a path is reversible, so one that starts at the edge always ends. Boards come from a seeded `rand` (`rules.js`, tested), so tests and the demo replay.
- A run of boards, with bulbs shown as lamps like Pair Up's chances (Easy and Medium 4, Hard 3). A turn that sends the beam into a short circuit burns one out; each board fixed lights one back (never past the start). The run ends when the last bulb is out, and the boards fixed are the score (`bent-beam:easy`, `:medium`, `:hard`; higher wins). The turns of the board in play are shown. Fixing a board in exactly `par` turns gets a gold line on the win card, one more silver, two more bronze, otherwise a plain cheer (three lines each, one picked at random). Undo takes back the last turn and counts as a turn. Starting over mid-run (New run or another level) asks first.
- The picture is one canvas, drawn by `scene.js` only when a mirror turns or the board changes size; nothing moves on its own, so the page costs nothing while you think. The lamps are small gears, the Notchup mark's shape: a lit one is filled and a waiting one an outline; a bolted mirror is white with rivets, so colour is never the only difference. Over the canvas is a grid of real buttons, one per cell ("Row 2, column 3: mirror, leaning right", "lamp, lit"), with one tab stop and the arrow keys moving around (`gridKeys`); Enter and Space turn a mirror and the status line says how many lamps are left. Cells are at least 24 px.
- The win: the board stops taking turns, but nothing the player lit goes away. A gold front runs along the lit beam from the housing (9 cells a second, at least 1.2 s), recolouring it from cyan to gold, with a rising laser tone at the start, a ping at each mirror and a sparkle at each gear lamp as the front passes; the board's border glows gold once, rising and falling over the run (a pseudo-element of the board whose opacity is the only thing that animates). The beam ends in a dot, small and cyan while you play (a socket at the board's edge, or on the wall it hits) and a big gold one once the front reaches it, so the beam clearly arrives somewhere. 0.7 s after the notch-up a "Board fixed" card (a medal line or a dry cheer, the turns and the boards fixed so far, and a Next board button) covers the board and the frame turns green. When the last bulb burns out the board goes red and an "Out of bulbs" card with a New run button covers it, and the score dialog opens over it if the boards fixed make the top 5 (nothing is offered for 0). No flash. With less motion the board is simply lit, without the run.
- `demo.js` plays an easy board by the real rules and the answer, ringing a mirror 0.45 s before it turns, about one a second, then the logo notches up and this browser's best runs show.

## Adding a game

## Which version is live

Every page has `<meta name="build" content="dev">`. On a Cloudflare deploy, the build command in `wrangler.jsonc` runs `scripts/stamp-build.mjs`, which turns it into the short commit and the date, for example `abc1234 2026-11-21` (view the page source). The commit comes from `WORKERS_CI_COMMIT_SHA`; without it the pages keep `dev`. A new game page needs the same tag (`tests/stamp.test.js`).

## Checks

- `./dev test`: rules, scores, memory, a privacy scan of every shipped file, the originality scan, the kit scan (`tests/kit.test.js`: neither a game nor another shared module may do again what a kit module does, such as sizing a canvas or asking for initials), the size budget, preload lists and the shared page HTML (`./dev sync`), the sitemap and the security headers.
- `./dev check`: the tests, then every page, its links and every module over HTTP.
- `./dev layout`: the hall and every game in `js/games.js` (a game with levels also at its last) in Chromium at 320×568, 360×640, 375×667, 390×844, 768×1024 and 1280×800. It fails on sideways scroll, a game page that scrolls at all, a game page without `overscroll-behavior: none`, a `[data-play]` area that does not have `touch-action: none` (so no pinch zoom while playing; `pan-x pan-y` only inside a frame that really overflows and has the `scrolls` class), text under 16 px, tap targets under 44 px (24 px on a game board), not exactly one `h1`, unlabelled fields, requests to other origins and console errors. The first run installs Playwright into `.local/tools`.
- `./dev bench`: what the hall and each game cost the main thread at 360 px (the hall also at 1280 px), with the CPU slowed 4x and a phone's pixel ratio, as a table to paste into a pull request (`scripts/bench.mjs`). A change meant to be faster, or one to shared code, shows the table from before and after, run on the same machine. Runs differ by up to about 20 %; less than that is noise. Headless Chromium draws in software, so the "task" column is much higher than on a phone; the "script" column is the games' own code.
